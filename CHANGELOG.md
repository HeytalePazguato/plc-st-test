# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased] — next: 0.0.1

### Added

- Memory and wall-time limits in `@plc-st/core`: `Limits` gains `maxAllocatedElements` (default 10,000,000 scalar slots per test) and `maxStringLength` (default 65,535), and the new `IecLimitError` is raised for allocation overruns (checked in `defaultValue` / FB instantiation before anything is allocated, so `ARRAY[0..99999999] OF LREAL` is rejected without building it), oversized STRING declarations, the wall-time deadline (`Session.startDeadline()` sets it from `maxExecutionTimeMs`; checked every 1024 loop iterations and once per cycle) and `maxCyclesPerTest` overruns, which previously threw `IecRuntimeError`.
- Simulated clock and cycle engine in `@plc-st/core` (`interpreter/clock.ts`, `interpreter/cycle.ts`): `SimClock` (bigint ns) and `CycleEngine.runCycles` / `runUntil`, where one cycle is cycle++ → clock advance → `session.preCycle` hooks → the suite's `Cycle` method (if any) → VAR_TEMP reset of the suite and its nested instances → `session.postCycle` hooks; `runUntil` parses its expression once per engine, returns the cycles consumed and throws `IecTimeoutError` naming the expression; `limits.maxCyclesPerTest` is enforced cumulatively per engine. `SessionHook` now receives the cycle number and `pou.ts` exports `resetInstanceTemps`.
- POU dispatch in `@plc-st/core` (`interpreter/pou.ts`): `callPou` resolves host functions, user FUNCTIONs, FB/program instances (user or host-implemented `FbStubDef`), METHODs (`inst.M()`, `THIS^.M()`, `SUPER^.M()`, bare `M()` in the owner) and ACTIONs (`inst.A()`, bare `A()` in the owner); named and positional argument binding, `=>` output bindings, VAR_IN_OUT aliasing (a non-variable argument is an error), VAR_TEMP reset per call, `limits.maxRecursionDepth` enforcement, and one `HOSTFN_SHADOWS_POU` warning when a host function hides a user POU. `instantiateFb` / `disposeFb` build nested instances (including arrays of FBs) and run the dialect `onInstantiate` / `onDispose` hooks once per instance; `createEvalContext` wires `callPou` into a root `EvalContext`, which gains optional `hooks`, `globals`, `clock`, `self` and `depth`. Expressions now evaluate `THIS` / `THIS^`, and `CallPou` receives the call's function node.
- `@plc-st/plugin-api` contracts (type-only except `version.ts`, `"sideEffects": false`): `PLUGIN_API_VERSION = 1` and `isCompatible(apiVersion)`; the shared value model (`IecType` string union, `IecValue`, `StructTypeInfo`/`EnumTypeInfo`/`AliasTypeInfo`/`ResolvedType`/`TypeResolver`); host functions and FB stubs (`Slot`, `CallArg`, `HostCallContext`, `HostFnDef`, `FbStubDef`, `VarSpec`, `FbIo`); `Ingestor` (`DetectCandidate`, `IngestOptions`, and a structural `SafeFsLike`); `Dialect` (`NodeHandler`, `DialectHooks`, `FbInstanceRef`, `TestStrategyKind`, `SuiteDescriptor`, `TestDescriptor`); `Simulator`/`SimulatorSession`; `Reporter`/`ReporterIo`; and `PluginModule`. `web-tree-sitter` is an optional peer (types only).
- `@plc-st/plugin-api` gains the full results contract: `RunResultsV1`, `SuiteResultV1`, `TestResultV1` and `CoverageSummaryV1` types, a hand-written JSON Schema (draft 2020-12, `$id` `https://plc-st.dev/schemas/results-v1.json`, `additionalProperties: false`) shipped as `@plc-st/plugin-api/schema/results-v1.schema.json`, and `validateResultsV1(x)`, a dependency-free structural validator returning JSON-pointer-like error paths (the only runtime code besides `version.ts`).
- Contract documentation for plugin authors: `docs/plugin-api.md` (every exported plugin-api type with field-level docs, the `apiVersion` major-mismatch policy, installed-only plugin discovery, and the note that dialect grammars must extend `tree-sitter-iec61131-3-st`), `docs/ingestor-contract.md` (detect/load semantics, the 1.0 / 0.5 confidence scale, the Tests-folder convention, SourceMap and SafeFs requirements, action units with `owner`), and `docs/results-schema.md` (results v1 field reference and the additive-only stability promise), linked from the mkdocs nav; `packages/plugin-api/test/docs.test.ts` fails if any exported name is missing from `docs/plugin-api.md`.
- `@plc-st/project-model` gains `SafeFs`, a filesystem confined to a project root: `resolve` normalises backslashes, resolves against the referencing file's directory, follows symlinks (including the nearest existing ancestor of not-yet-existing paths, and rejecting dangling links) and throws `ConfinementError` (`code: 'PATH_ESCAPE'`) when the real path leaves the root, comparing case-insensitively on Windows and macOS; `readText` enforces a size limit (default 16 MiB, `FileTooLargeError`), strips a UTF-8 BOM and falls back to latin1 for invalid UTF-8; plus `exists` and `list`.
- `@plc-st/project-model` gains `parseXml`, a secure positional XML reader built on `sax`: it returns an element tree (`XmlElement`) whose CDATA sections (`XmlText`) carry the 1-based line/column of their first content character (CRLF preserved), rejects DOCTYPE and ENTITY declarations with `XmlSecurityError`, caps nesting depth at 256 and total elements at 200,000, and surfaces syntax errors as `XmlParseError` with file/line/column; plus `child`, `children`, `textOf` and `firstCdata` helpers.
- `@plc-st/project-model` now exports the vendor-neutral project types (`Project`, `SourceUnit`, `UnitRole`, `Vendor`, `LibraryRef`, `ProjectWarning`) and `SourceMap`, which maps 1-based generated line/column positions back to original files (`OriginalLocation`) from non-overlapping segments, with `identity`, overlap/invalid-input rejection, and a JSON round-trip.
- Changesets for independent per-package versioning (`.changeset/config.json`, `pnpm changeset` / `version-packages` / `release` scripts) and a "Versioning and changelogs" section in CONTRIBUTING.md. The repo-root `VERSION` file is removed (documented deviation from project-blueprint); `@plc-st/core` now reads its exported `VERSION` from its own `package.json`.
- Package skeletons for the rest of the monorepo — `@plc-st/plugin-api`, `@plc-st/project-model`, the `plc-st-test` CLI (`src/cli.ts` moved to `packages/cli`), `@plc-st/ingestor-{generic,twincat,br}` and `@plc-st/dialect-{standard,twincat,br}` — each with TypeScript project references, a Vitest project, and a smoke test; `pnpm build` now builds all ten packages in dependency order. Dependency boundaries (project-model imports nothing, plugin-api only project-model, ingestors never core/CLI/dialects, dialects never core/ingestors) are enforced by ESLint `no-restricted-imports` per package glob and by `test/architecture.test.ts`, which checks every `packages/**/package.json` and all source imports.
- `parseExpressionFragment` / `parseStatementFragment` parse an ST expression or statement list by wrapping it in a throwaway POU, throwing `IecError('invalid fragment: …')` with a fragment-relative position on syntax errors; plus a grammar-compatibility test (`abiVersion >= 14`, zero diagnostics on an FB/IF/CASE/FOR/METHOD sample).
- Single-package TypeScript scaffold: strict `tsconfig` (ES2022 / NodeNext), vitest, eslint flat config, pnpm via corepack, and a `ci.yml` matrix across Ubuntu / macOS / Windows on Node 20 and 22.
- Parser wrapper over `web-tree-sitter` that loads the `tree-sitter-iec61131-3-st` `.wasm` grammar (`initParser`, `parseSource`, `walk`) and surfaces ERROR / MISSING nodes as diagnostics with 1-based line and column.
- Numeric fidelity module: `IecType`, exact two's-complement `wrapInt`, `froundReal` for 32-bit REAL, IEC implicit-widening, and BigInt arithmetic for the 64-bit types (LINT / ULINT / LWORD).
- Runtime value model: the `IecValue` union plus `defaultValue`, deep `cloneValue`, and bit-exact `valueEquals`.
- Cross-file symbol table: POUs, VAR blocks, TYPE declarations (enums / structs), and FB-instance detection, with a `caseSensitive` mode for dialects such as B&R.
- Interpreter foundation shared by the upcoming interpreter tasks: the `EvalContext` / `Slot` / `CallPou` / `ControlSignal` contracts, `DEFAULT_LIMITS`, and the `IecTimeoutError` class.
- `hotfix/<version>` branch convention for emergency patches cut directly from `main` when `develop` has unfinished work that can't ship.
- Repo settings now enable `delete_branch_on_merge=true` via `gh repo edit`.
- Dependabot configured for the monorepo (`.github/dependabot.yml`, version 2): weekly npm updates targeting `develop`, split into `prod` and `dev` groups with a 7-day cooldown matching `minimumReleaseAge`; monthly grouped `github-actions` updates; monthly `docker` updates for `/integrations/docker`.
- `@plc-st/core` `Session` and `Registry` (`src/session.ts`): per-run host-function / FB-stub registries (later registration wins, one collision warning naming both sources), node handlers, warnings, cycle hooks, and `CoverageSink` / `MockStore` placeholders; `EvalContext` now carries `session`. A test guards against new module-level mutable state.
- `@plc-st/core` scope chain (`src/interpreter/scope.ts`): `Scope` (case mode from `Session.caseSensitive`, redeclaration throws `IecError`), immutable innermost-first `ScopeChainImpl`, VAR_IN_OUT binding by aliasing the caller's `Slot`, and `resetTemps` which reinitialises only VAR_TEMP entries in place so aliases stay valid; shared `caseKey` helper in `src/case.ts`.
- `@plc-st/core` `buildSymbolTableFromProject(project, language, { caseSensitive, preprocess? })`: parses each `SourceUnit` separately (a `preprocess` that changes a unit's line count throws `IecError`), attaches `role: 'action'` units to their owner POU as `Pou.actions` (`Action { name, bodyNodes, unitId }`; unknown owner or duplicate action name → diagnostic), records `Pou.isTest` / `Pou.unitId`, and adds `SymbolTable.locate(node)`, which maps any node (including nodes inside action fragments, minus the wrapper line) back to its original file through the unit's `SourceMap`. `SymbolTable.diagnostics` is now `{ location: OriginalLocation; message }[]` and includes mapped syntax errors; `buildSymbolTable(files)` keeps working by treating each file as an identity-mapped unit. `parser/fragment.ts` exports `wrapStatementFragment` and `STATEMENT_FRAGMENT_LINE_OFFSET`.
- `@plc-st/core` expression evaluator (`src/interpreter/expressions.ts`): `evalExpression(node, ctx, enumHint?)`, `evalLValue(node, ctx)` (live slots for struct/FB members and array elements) and `evalCall(node, ctx)`. Covers integer literals in every base with `_` separators, typed literals (range-checked), REAL/LREAL with exponents, STRING/WSTRING `$` escapes, `T#`/`TIME#`/`LTIME#` durations (compound and fractional) as nanosecond `bigint`, `D#`/`TOD#`/`DT#` folded onto TIME, identifiers, multi-dimensional row-major indexing with bounds errors (`index 4 out of bounds [0..3] for arr at <file>:<line>`), struct and FB member access, qualified and bare enum members (partner type, else unique search, ambiguity is an error), unary `-`/`+`/`NOT`, arithmetic through numeric.ts with IEC widening (untyped literals adopt their typed partner's type when they fit; `**` yields REAL/LREAL), `MOD`, TIME arithmetic, comparisons on numbers/enums/strings/TIME/BOOL, `AND`/`&`/`OR`/`XOR` on BOOL and bitwise on integer/bit-string types, and calls via `ctx.callPou` (variables passed with their `Slot`, `=>` bindings included). Unknown node types go to `session.nodeHandlers` before raising `unsupported construct <type> at <file>:<line>`; runtime errors carry the original-file location. `SymbolTable.getEnums()`, `values.elementaryType()` and `numeric.isIntType` are now exported, and an enum variable initialised with a qualified member (`E_Color.Blue`) now gets that member instead of the first one.
- `@plc-st/core` statement executor (`src/interpreter/statements.ts`): `execStatement(node, ctx)` / `execBody(nodes, ctx)` returning a `ControlSignal`, plus `storeValue(slot, value, node, ctx)`. Assignment stores a converted copy in the target's declared representation (integer wrap, REAL single-precision rounding, implicit REAL → integer rounding half to even, STRING(n)/WSTRING(n) truncation, enum/struct/array type checks; bare enum members resolve against the target's enum). Covers IF/ELSIF/ELSE, CASE (values, `a..b` ranges, lists, bare and qualified enum labels, ELSE), FOR (BY with negative or expression step evaluated once, zero step raises, body skipped when bounds and step disagree, control variable ends one step past the end), WHILE, REPEAT/UNTIL, EXIT (innermost loop), CONTINUE, RETURN, invocation statements and empty statements. Each loop execution is capped at `limits.maxLoopIterations` with an error naming the loop's original `<file>:<line>`; taken branches are reported to `session.coverage` as `<file>:<line>:<kind>` only when a sink exists; unknown statement types go through `session.nodeHandlers` before raising `unsupported construct`. The scalar `IecValue` gains an optional `maxLength` (declared STRING(n) capacity, set by `defaultValue` and kept by `cloneValue`), TIME defaults are now `0n` to match the evaluator's nanosecond bigints, and `expressions.ts` exports its `where` / `fail` location helpers.

- `@plc-st/core` test strategies and suite discovery (`src/runner/strategies.ts`, `src/runner/discovery.ts`): `discoverSuites(table, { strategy, pattern })` (default pattern `TEST_*`, `*`/`?` globs matched per the table's case mode) turns test-unit FUNCTION_BLOCKs (and PROGRAMs for the action strategies) into `SuiteDescriptor`s — `method`, `action` or `method-or-action` (methods if any, else actions) — excluding SetUp/TearDown/Cycle from the tests but recording them, locating everything through the source maps, and returning a `SUITE_EMPTY` warning for suites without tests.

### Changed

- `@plc-st/core` now takes `IecValue`, the type-resolver types, `Slot` and `CallArg` from `@plc-st/plugin-api` (re-exported from `interpreter/values.ts` / `interpreter/context.ts`, so existing imports keep working), and `IecType` is now an `as const` object plus a string-union type instead of a TypeScript `enum`, so plugin-built values and core values share one type.
- `ci.yml` rewritten for the monorepo: `test` job (ubuntu/macos/windows × Node 24/26: frozen install, lint, build, test), a PR-only `changeset` job (`pnpm changeset status --since=origin/develop`), and a `workflow-lint` job running actionlint (digest-pinned official image) and zizmor (pinned `1.31.1`); every action is pinned by full commit SHA with a version comment, token permissions are `contents: read`, and checkout no longer persists credentials. Pushes to `release/**` no longer trigger CI (release PRs are covered by `pull_request`; zizmor flags that trigger as a cache-poisoning risk).
- Parser API is now multi-grammar: `loadGrammar(wasmPath)` initialises web-tree-sitter once and caches one `Language` per absolute path, `baseGrammarPath()` resolves the bundled base grammar, and `parseSource(language, source, filePath)` takes the language explicitly (replacing the module-global `initParser()`).
- Converted the repository to a pnpm workspace monorepo: the existing engine moved (history preserved via `git mv`) to `packages/core` as `@plc-st/core`, the root `package.json` is now the private `plc-st-test-monorepo` workspace root, builds use TypeScript project references (`tsc -b` with `tsconfig.base.json`), and Vitest runs per-package via `test.projects`. Toolchain bumped to pnpm 11.28.9, Node >=24, TypeScript ~6.0.3, Vitest 5, ESLint 10, typescript-eslint 8.72, `@types/node` ~24, and `web-tree-sitter` ~0.27.1.
- Pin `tree-sitter-iec61131-3-st` to 0.1.2, whose external scanner reserves the `END_*` terminators; a forgotten `END_IF` now yields a precise `MISSING "END_IF"` node instead of collapsing the whole POU into a single error.
- Branch flow diagram now shows two paths to `main`: `release/*` for planned releases and `hotfix/*` for emergency patches. PRs to `main` must originate from one of these two — never from `develop` directly, because the `delete_branch_on_merge` setting would wipe `develop` on the remote on every release.

### Why

Discovered while shipping the first 0.0.1 of a project that used this blueprint: when CI/release-workflow fixes were PR'd from `develop` directly to `main`, the auto-delete-on-merge setting deleted `develop` on the remote each time. The fix is procedural — always route through `release/*` or `hotfix/*` — so the blueprint now codifies that.
